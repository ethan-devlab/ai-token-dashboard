# Local AI Token Dashboard Design System

## 1. Intent and visual thesis

This is a desktop-local engineering surface for understanding a selected period of Codex or Claude Code usage: total tokens, the API-equivalent estimate, source quality, and individual sessions. It should feel like a restrained observability console, not a consumer SaaS product: a calm cool-gray field, subtle layers, dense but readable information, and one teal action color. The selected provider owns its snapshot, pricing, filters, budgets, and refresh state. The existing JSONL parsers and their accounting semantics remain authoritative; the UI only makes those facts inspectable.

## 2. Design tokens

All presentation values come from `public/styles/tokens.css`; no remote font, CDN, image, gradient, or one-off branded asset is used.

## 3. Typography and content hierarchy

The interface supports Traditional Chinese and English, retaining established technical English labels such as `Input`, `Output`, `Cached`, and model names where they are the clearest domain terms. The hierarchy is: selected period and refresh/update actions; four executive KPIs; the token breakdown; system metadata and any real data-quality warning; login-plan usage, comparison, and budgets; then the interactive trend and model breakdown, session explorer, and pricing disclosure. KPI numerals are prominent without becoming marketing headlines. Exact values, paths, and diagnostic source labels use the mono stack with lower contrast.

## 4. Layout, responsive behavior, and scroll ownership

The supported product surface is desktop only: 1440–1600px content frame and a 960px minimum inline size. There is no mobile or tablet adaptation in this scope. The document owns vertical scrolling. The session table alone owns local horizontal overflow; its header stays sticky inside that container. The application shell, summary, metadata, and disclosures must not acquire nested scroll regions. Controls may wrap inside the dedicated period context without displacing the visual hierarchy at supported desktop widths. The compact dashboard header wraps its tools and gives the explicit JSONL refresh action the primary accent. Trend and model panels share a 3:2 grid at widths of 1200px or more; they stack at smaller supported desktop widths. Quota windows fill the available row.

## 6. Interaction and motion

Range, search, sort, and paging obtain projections from the latest successful in-memory snapshot without starting a new JSONL parse. The client keeps a small, bounded cache of already-rendered dashboard projections. A cache hit may render immediately only when it exactly matches the active URL query. On a cache miss, the prior projection is explicitly stale, its metrics and explorer are busy, and the projection status announces that replacement values are loading. Only the explicit refresh control calls the rescan endpoint; the server double-buffers the result and retains the previous snapshot if parsing fails. JSONL parsing executes outside the HTTP event loop so static, diagnostic, and snapshot responses remain available during a scan. Range, search, and sort state are mirrored in the URL, while language, density, unit, detail, trend, and column preferences stay in local storage. The GitHub update check is a separate explicit user action and never runs automatically. The Canvas trend is a recorded novel interaction informed by the nearest restrained data-table pattern: pointer and keyboard selection anchor a non-interactive detail popup to the closest point; it flips below a near-top point and aligns at an edge so values stay visible. It uses no motion because no state transition benefits from animation. Focus indication is a 3px teal outline with offset. Enabled actions have hover and pressed states; table-row shading supports reading. Busy buttons reserve the width of both idle and operation labels to avoid a layout jump. Exact/detail/column preference changes preserve the current chart selection and table disclosure. Loading uses a low-contrast 1.2s opacity skeleton and must not shift layout. `prefers-reduced-motion: reduce` suppresses nonessential animation and transitions while preserving actual loading/error text. Escape closes the session drawer first, then the view menu with focus returned to its summary, then clears session search.

## 7. Accessibility and security constraints

Controls have explicit labels; the summary, insight, and explorer expose `aria-busy`; quality/error and projection text use polite live regions; and the semantic table keeps headers. The active `lang`, metadata, title, dates, numbers, and currency follow the selected `zh-Hant` or `en` locale. The Canvas trend exposes a short summary, a live selected-point value, keyboard navigation, and a semantic table alternative. The local static shell stays same-origin under a restrictive CSP and `nosniff`; it must not expose raw session JSONL or conversation content. The settings endpoint is available only when the configured server host is loopback, requires the same Origin and bounded JSON body, allow-lists its `.env` keys, and atomically writes the local file; saved values require a restart before they affect the running process. GitHub checking only reads a fixed `owner/repo` latest-release endpoint when a user asks. Browser visual QA is directly performed by the root agent at desktop widths only; it is not delegated.

## 8. Scope, verification, and accepted debt

The desktop UI review and its measured validation results are recorded in `docs/ui-ux-review.md`. The four KPI cards use four columns at wide desktop widths and two columns below 1200px to keep long currency values readable.

The approved full refactor is recorded in `docs/dashboard-ui-refactor-plan.md`. Phase 1 repairs are recorded in `docs/dashboard-deep-audit.md`: hidden state takes priority over component display rules; session density affects only its table; insight panels align at their starts; view options open from the trigger's start edge. The current native line chart uses actual timestamps and leaves missing intervals disconnected. Chart, summary, model, row, and drawer cost labels share lower-bound formatting. Complete positive costs below USD 0.000001 show a threshold; partial subtotals below that precision use a scientific lower bound. Session row and drawer usage dates use the displayed projection's timezone; operational check/reset dates retain browser-local formatting. The modal drawer keeps its heading and Close control stable, makes background regions inert, contains focus, and restores it on close. Custom range errors are associated with both date fields. Checkbox facets are implemented in Phase 2. Production chart modes, quota composition, and settings dirty-state behavior remain in their planned phases.

Phase 3 has a separate `/chart-comparison.html` prototype with local native/uPlot adapters, three presentation modes, bars/lines, shared readout and interval controls, and explicitly labeled test fixtures. Its assets and preference key are separate from the production dashboard. Applying an interval affects only the prototype's local usage projection; quota periods remain independent. See `docs/chart-engine-comparison.md` for measurements and verification limits. The production engine remains a user decision; this checkpoint does not complete Phase 3.

Focused verification covers syntax, the server’s static/root/CSP boundary, route traversal rejection, parser fixture semantics, server-side aggregation, pagination, URL state, local view preferences, the bounded projection cache, watcher status propagation, pricing disclosure data, and loopback-only atomic settings persistence. Direct visual verification checks the shipped desktop page and its loading, populated, warning, error, range, explorer, drawer, pagination, disclosure, and settings states. No mobile/tablet work, remote dependencies, analytics, glass effects, neon gradients, fake data, or silent data-semantic changes are accepted.

The server keeps `GET /api/summary` as its compatibility response. `GET /api/dashboard` accepts the validated range, search, sort, offset, and limit query parameters and returns range aggregates plus the first session page. `GET /api/sessions` returns subsequent filtered pages only. `POST /api/refresh` is the only rescan path; all current snapshot responses contain scan timestamp, snapshot version, and refreshing state. `GET /api/update` is disabled unless `UPDATE_REPOSITORY=owner/repo` is valid and never accepts a caller-provided URL. Dashboard routes expose summaries rather than raw JSONL or conversation content; model pricing is loaded from `server/pricing.json`.

## 8. Style ownership

Both pages load `tokens.css`, `base.css`, and shared `components.css`. Dashboard composition and facets load from `dashboard.css`; tables, charts, model ranking, pricing, and drawer content load from `data-views.css`. Settings loads only `settings.css` in addition to shared styles. Shared styles own action states, labeled controls, status notices, panels, and the modal shell. Density and column selectors are scoped to the session explorer.
