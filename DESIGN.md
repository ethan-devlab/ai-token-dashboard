# Local AI Token Dashboard Design System

## 1. Intent and visual thesis

This is a desktop-local engineering surface for understanding a selected period of Codex or Claude Code usage: total tokens, the API-equivalent estimate, source quality, and individual sessions. It should feel like a restrained observability console, not a consumer SaaS product: a calm cool-gray field, subtle layers, dense but readable information, and one teal action color. The selected provider owns its snapshot, pricing, filters, budgets, and refresh state. The existing JSONL parsers and their accounting semantics remain authoritative; the UI only makes those facts inspectable.

## 3. Typography and content hierarchy

The interface supports Traditional Chinese and English, retaining established technical English labels such as `Input`, `Output`, `Cached`, and model names where they are the clearest domain terms. The hierarchy is: selected period and explicit actions; four KPIs; a compact account-quota strip; token breakdown, metadata, and quality; trend and model ranking; Session; comparison and budgets; maintenance disclosures. Overview costs use two decimals; exact details use up to six decimals. Partial overview bounds round down so the display cannot overstate the known subtotal. Small positive partial costs retain sufficient detail; unknown values stay unavailable. Exact values, paths, and diagnostics use the mono stack.

## 4. Layout, responsive behavior, and scroll ownership

The supported product surface is desktop only: 1440–1600px content frame and a 960px minimum inline size. The document owns page scrolling. The Session table owns both overflow directions within a 32rem height limit, has a named keyboard-focusable scroll region, and keeps its header sticky. Paging remains outside this region. Trend and model data tables have their own 20rem limit. The shell, summary, metadata, and other disclosures have no nested scrolling. Controls wrap at supported widths. Trend and model panels share a 3:2 grid from 1200px and stack below it. Quota summaries wrap below the KPIs; full quota cards expand in place. Pricing cards use label/value rows, with two columns below 1200px. Settings Save stays visible at the bottom while the document scrolls.

## 6. Interaction and motion

Range, search, sort, and paging obtain projections from the latest successful in-memory snapshot without starting a new JSONL parse. The client keeps a small, bounded cache of already-rendered dashboard projections. A cache hit may render immediately only when it exactly matches the active URL query. On a cache miss, the prior projection is explicitly stale, its metrics and explorer are busy, and the projection status announces that replacement values are loading. Only the explicit refresh control calls the rescan endpoint; the server double-buffers the result and retains the previous snapshot if parsing fails. JSONL parsing executes outside the HTTP event loop so static, diagnostic, and snapshot responses remain available during a scan. Range, search, and sort state are mirrored in the URL, while language, density, unit, detail, trend, and column preferences stay in local storage. The GitHub update check is a separate explicit user action and never runs automatically.

Pointer preview updates overlays through one animation frame; it does not redraw plots or announce each movement. The pinned readout stays outside the plot. Mode, mark, metric, locale, unit, density, exact values, details, and columns preserve chart selection and table disclosure. Mode, mark, locale, and metric can rebuild plot frames while retaining controller state. Data/resize updates reuse uPlot instances. One ResizeObserver, pending pointer frame, and plot instances are cleaned up on destruction. Query changes reset zoom and interval selection; a failed query retains the displayed source scope. Apply writes numeric `from`/`to` bounds so repeated civil hours remain distinct, updates local usage only, and disables export/application while the projection is stale. Return history is page-local; reload retains current exact bounds but clears this history. Quota periods are independent.

Focus indication is a 3px teal outline with offset. Enabled actions have hover and pressed states; table-row shading supports reading. Busy buttons reserve the width of both idle and operation labels to avoid a layout jump. Loading uses a low-contrast 1.2s opacity skeleton and must not shift layout. `prefers-reduced-motion: reduce` suppresses nonessential animation and transitions while preserving actual loading/error text. Escape ends chart preview when focus is in a plot. Elsewhere it closes the session drawer first, then the view menu with focus returned to its summary, then clears session search.

## 7. Accessibility and security constraints

Controls have explicit labels; the summary, insight, and explorer expose `aria-busy`; quality/error and projection text use polite live regions; and the semantic table keeps headers. The active `lang`, metadata, title, dates, numbers, and currency follow the selected `zh-Hant` or `en` locale. Each plot exposes a named keyboard group, help text, external readout, and a semantic table alternative. Only explicit pin or keyboard selection updates its polite announcement; vendor canvas content is hidden from accessibility output. The local static shell stays same-origin under a restrictive CSP and `nosniff`; it must not expose raw session JSONL or conversation content. The settings endpoint is available only when the configured server host is loopback, requires the same Origin and bounded JSON body, allow-lists its `.env` keys, and atomically writes the local file; saved values require a restart before they affect the running process. GitHub checking only reads a fixed `owner/repo` latest-release endpoint when a user asks. Browser visual QA is directly performed by the root agent at desktop widths only; it is not delegated.

## 8. Scope, verification, and accepted debt

The desktop UI review and its measured validation results are recorded in `docs/ui-ux-review.md`. The four KPI cards use four columns at wide desktop widths and two columns below 1200px to keep long currency values readable.

The approved full refactor is recorded in `docs/dashboard-ui-refactor-plan.md`. Phase 1 repairs establish hidden-state precedence, scoped density, aligned panels, and visible view options. Chart timestamp geometry and detailed cost qualifiers are implemented. Complete detail costs below USD 0.000001 use a threshold; smaller partial subtotals use a scientific lower bound. Session usage dates follow the displayed query; operational dates retain browser-local formatting. A retained Session detail request uses the displayed query's conditions and keeps its timezone. The modal drawer keeps its heading/Close control, inactive background, and contained focus. Close returns to the connected trigger, a replacement button for the same Session, or Search if that Session no longer exists. Missing diagnostic counts show `—`; measured zero stays zero. Custom range errors are associated with both fields. Checkbox facets are complete in Phase 2, charts in Phase 3, and composition, quota, recovery, and settings dirty state in Phase 4. Phase 5 completed local integration review, including unavailable-provider isolation and exact-range export parity. Browser download completion and native unload-warning UI remain unverified in the in-app browser. Windows controls, screen readers, and populated Claude require their own follow-up; local evidence does not certify those platforms.

The Phase 3 comparison is archived at commit `2a4773d`. The user selected uPlot 1.6.32; the dashboard now loads one local renderer and its pinned CSS. The MIT license is bundled next to the vendor module. The comparison route and native renderer are removed. Test fixtures live only under `tests/fixtures`. See `docs/chart-engine-comparison.md` for historical measurements and `docs/dashboard-deep-audit.md` for production verification. No new performance claim is based on the archived benchmark.

Focused verification covers syntax, the server’s static/root/CSP boundary, route traversal rejection, parser fixture semantics, server-side aggregation, pagination, URL state, local view preferences, the bounded projection cache, watcher status propagation, pricing disclosure data, and loopback-only atomic settings persistence. Direct visual verification checks the shipped desktop page and its loading, populated, warning, error, range, explorer, drawer, pagination, disclosure, and settings states. No mobile/tablet work, remote dependencies, analytics, glass effects, neon gradients, fake data, or silent data-semantic changes are accepted.

The server keeps `GET /api/summary` as its compatibility response. `GET /api/dashboard` accepts the validated range, search, sort, offset, and limit query parameters and returns range aggregates plus the first session page. `GET /api/sessions` returns subsequent filtered pages only. `POST /api/refresh` is the only rescan path; all current snapshot responses contain scan timestamp, snapshot version, and refreshing state. `GET /api/update` is disabled unless `UPDATE_REPOSITORY=owner/repo` is valid and never accepts a caller-provided URL. Dashboard routes expose summaries rather than raw JSONL or conversation content; model pricing is loaded from `server/pricing.json`.

## 9. Style ownership

Both pages load `tokens.css`, `base.css`, and shared `components.css`. Dashboard composition and facets load from `dashboard.css`; tables, charts, model ranking, pricing, and drawer content load from `data-views.css`. Settings loads only `settings.css` in addition to shared styles. Shared styles own action states, labeled controls, status notices, panels, and the modal shell. Density and column selectors are scoped to the session explorer.

Spacing uses the existing tokens: 4px between an eyebrow and its title, 8px before a supporting trend/model summary or compact-panel content, 12px before drawer diagnostics and budget results, and 16px between major sections. Summary grid gaps own the quota panel's external spacing; the panel has no additional block margins. Empty projection text and empty active-chip containers do not consume layout space. Period headings can wrap within the desktop frame. Settings leave 16px between the dirty-status text and the first fieldset legend. The drawer title can wrap, while Close retains its intrinsic single-line width and a 16px title/action gap.

Shared controls distinguish idle disabled primary actions with a muted surface and text. Busy actions retain their variant, named operation label, wait cursor, and reserved label width. Enabled text inputs and native selects use a subtle hover border. Invalid input borders follow common control defaults in the cascade and retain the danger color on hover. Settings labels have stable accessible names; field errors remain separate descriptions. Trend Apply and Return use the shared busy-label helper, prevent duplicate pending actions, and clear pending state in `finally`. Completion moves focus to the Start boundary only when focus has fallen to the document or remains on the now-disabled action. Focus on another control is preserved.
