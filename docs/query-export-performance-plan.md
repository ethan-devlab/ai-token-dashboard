# Query and streamed export performance plan

Date: 2026-10-01 (Asia/Taipei). Status: decisions Q40–Q50 confirmed; implementation not started. Source baseline: a0ad92c. Measurement checkpoint: 8a488b1 and [performance-baseline.md](performance-baseline.md).

## Selected scope and targets

| Decision | Confirmed policy |
| --- | --- |
| Q40 | Improve queries and exports together: reduce repeated calculation and unused projection work; bound output memory |
| Q41 | Use the existing 150000 observations / 1500 Sessions and 10000 pricing versions as the first acceptance workload |
| Q42 | First dashboard at most 1500 ms; loaded-snapshot dashboard/model filter at most 250 ms; Session page/detail at most 100 ms; each of four exports at most 500 ms |
| Q43 | Normal benchmark request sequence observed maximum RSS at most 512 MiB |
| Q44 | Remove the 32 MiB export limit and allow large streamed output; do not retain the old 413 policy as the selected behavior |
| Q45 | Replace frontend full Blob collection with native browser download management; validate the displayed projection first; report handoff, never claim a file was saved |
| Q46 | Interrupted/cancelled downloads restart from the beginning; no Range resume; browser manages partial files |
| Q47 | An already started transfer completes its original query/snapshot/pricing basis despite later refresh/filter changes. Before handoff Q19 conflict reload and explicit retry remain |
| Q48 | Transfer-stage additional observed RSS at most 16 MiB; preparation and the existing snapshot remain within Q43's normal-sequence limit. No complete output allocation |
| Q49 | At most one prepared or active export per dashboard process; reject another immediately as busy; no queue |
| Q50 | Ready but unused export expires after 2 minutes. Transfer stops after 60 seconds without progress or 30 minutes total. Release snapshot/resources; restart from the beginning |

Q48 replaces Q43's earlier rejected-export memory target after Q44 removed the size cap. The 512 MiB target covers the normal fixed workload, not arbitrary input files or a simultaneous refresh holding multiple large snapshots. Removing the cap changes the API's former EXPORT_TOO_LARGE behavior. All formats, escaping, formula protection, metadata, accounting, current-basis pricing, projection guards, local security and manual browser update policy remain.

Latency targets use the same local machine, copied application, synthetic inputs, parse concurrency, sequential workload and complete HTTP consumption as the baseline. They are acceptance goals, not cross-hardware guarantees. Distinguish first scan, loaded-snapshot new query, repeated query, prepare response, transfer and total export time. Do not report a fast cached hit as proof that a new filter meets its target. Prepare plus complete transfer must meet the export target on the normal workload. Slow/cancelled/large-file cases validate resource and lifecycle behavior separately.

## Implementation boundaries

Root owns implementation, integration, runtime and desktop QA. No agents, production requests/restart, real credentials/settings, install, push or release. Native Service/Tray, archive lifecycle R02, real-user distribution, Windows certification, historical pricing, automatic UI synchronization and observation tables are outside this phase.

1. Own server/dashboard-data.mjs and only the focused query/projection helper needed beside it. Separate selected Session/event aggregation from page/detail/presentation. Reuse prepared values where safe, skip facets/trend/complete Session-row materialization when a report does not require them, and use bounded per-query memoization for repeated timezone/rate work. Preserve exact IANA/DST boundaries and all selected accounting/quality semantics. Detail must find its Session before computing unrelated Session costs; page totals still describe all matching data. Model facets must retain the current model-filter-independent membership rules.
2. If measurement needs a projection cache, keep it small and bounded. Scope by Provider, snapshot, pricing revision/availability and full normalized query/range/time semantics. Offset/limit may select a page from the same prepared projection. Evict obsolete entries; never share Provider data or grow one entry per arbitrary search indefinitely. Do not cache live refresh diagnostics as query truth: retained-snapshot failures such as FA24 must remain current even when projection identity is unchanged. Q47's active export owns its pinned immutable data independently of cache eviction.
3. Own a focused server/export-service.mjs and server.mjs route integration. Prepare a stable export plan from one verified projection; encode incrementally with bounded chunks and response backpressure. Count exact UTF-8 output length without constructing the complete body, then retain Content-Length and existing format/filename/security/scope headers. Test long fields, quotes, CR/LF, Unicode boundaries, CSV formula prefixes and empty metadata rows. Do not append an error JSON object to a partially written CSV/JSON response.
4. Preserve GET /api/export for direct callers, now with streamed output and the same process-wide slot. Add same-origin POST /api/export/prepare using existing query validation/guards, and a one-use GET download URL for native UI handoff. Preparation verifies the displayed projection and pins query, snapshot and pricing basis; the later download does not silently rebuild from current state. Tickets are unpredictable, memory-only and short-lived; do not log, persist or send them externally. Missing/expired/used tickets fail before bytes are sent. Another export returns 429 EXPORT_BUSY. Explicit Range attempts fail with 416 RANGE_NOT_SUPPORTED; no resume is advertised. Before-header failures retain the normal JSON error envelope. After-header failure closes the response so a truncated file cannot appear complete under its declared length.
5. Own public/scripts/dashboard.mjs, request handling only where required, export controls in public/index.html and bilingual i18n.mjs. Prepare through the existing request ownership/generation rules, handle conflict by full reload with no automatic download, then hand off to the native browser. Remove response.blob/object-URL use from the product export path. Superseded preparation must not launch a download or publish late errors/busy state. Starting a native download ends page-owned preparation; later query changes do not cancel that transfer. Do not infer saved bytes or native cancellation from anchor activation. Busy/expiry/failure text must make retry-from-start clear.
6. Release the slot and pinned data on completion, connection close/error, deadline, failed preparation, unused-ticket expiry and process shutdown. Honour response backpressure rather than creating an unbounded write queue. Progress means bytes accepted/drained by the server transport, not browser disk completion. Service shutdown interrupts active transfers; it does not keep a process indefinitely alive. Prepared response loss can leave a ticket until the bounded unused expiry; no automatic restart or background takeover is implied.

The route and cache boundaries above are implementation details chosen to preserve selected behavior and published direct export access. They add no framework, package, database, disk spool or resumable-file store. If measurements show these boundaries cannot meet a confirmed target, report the evidence and request a target/scope decision; do not weaken accounting, secretly cap exports or claim targets passed.

## Focused acceptance

Implement before adding focused regression checks. Keep [performance-baseline-evidence.json](performance-baseline-evidence.json) immutable as the historical capped-export measurement. Update the runnable benchmark for the new policy or add a focused acceptance harness; do not leave the historical 413 assertion as the current behavior. Retain its 10000/50000/150000 workloads and archive checks. Add the following only where needed:

- Correctness: selected observation totals, complete/partial/unknown pricing, archive-unavailable cost, cumulative/reset/conflict quality, mixed-model facets, query/search/sort membership, full unpaged export scope and Session-detail limits. Run affected existing accounting/projection/calendar/client checks, not an unrelated broad matrix. Use copied HTTP fixtures with all upstream fetch blocked.
- Isolation: cache miss/hit and new filter, same-version failure warning, Provider switch, pricing availability/revision change, new snapshot and time-bound changes. Cached projection and an active old-version export must never mutate after a refresh. Exercise query/export overlap without claiming a general concurrent-load SLA.
- Bytes: four formats, empty metadata, formulas/quotes/newlines, UTF-8 and very long fields. Validate exact Content-Length, saved bytes, projection/pricing/range metadata and full Session row count. The previous adversarial 500 × 70000-character fixture must now produce a complete file larger than 32 MiB, with bounded transfer memory. HTTP test clients may collect bodies for byte verification; product UI must not do so.
- Lifecycle: one slot shared by prepared and direct routes; second request busy; one-use ticket; expiry; abort/error; stalled client; total deadline; unsupported Range; shutdown. Use injected clocks/timers for long deadlines, plus real HTTP cancellation/backpressure. Verify resources are released and the next export works. Do not sleep for the full 30-minute deadline in QA.
- Desktop: root tests English/Traditional Chinese at desktop dimensions with native browser downloads. Recheck all four saved files, >32 MiB actual saved CSV, save cancellation, interrupted transfer/partial-file handling, stale preflight, query change during download, busy/expired/retry text and late preparation errors. Check settings/Provider flows only where shared request code changed. Report a native capability limit instead of claiming unobserved saved-file success.
- Performance: measure first and warm/new-query paths, Session page/detail, all four total exports, request bytes, handler heap/RSS and external RSS samples under the same sequence. Add transfer-stage before/after and sampled memory; test a slow consumer so a tiny response cannot mask an unbounded queue. Keep the sampling limits explicit. Do not change fixture cardinality, force GC or bypass the pricing/trend work required by a response to claim a target passed.

Before development, confirm this complete plan with the user and commit the plan checkpoint. After implementation, review intended files, run the required bounded checks, commit the completed phase, then present the next decision dialog. No production rollout is included.
