## Requests and errors

Host validation requires a single valid authority and accepts the configured authority and existing loopback aliases. For wildcard binds, it also accepts the request socket's actual local IP with the configured port, including IPv4-mapped IPv6 addresses. Other interface addresses, external domain names, trailing-dot/numeric aliases and wrong ports are rejected. Hostnames are case-insensitive; omitted HTTP ports mean 80 and must match the configured port. Request targets must use origin-form and cannot change the admitted authority. Forwarded headers never change admission or the expected origin. Wildcard loopback destinations also accept the existing localhost/loopback Host aliases. Settings require a real loopback source, loopback destination and local loopback URL, independently of the bind address. Settings over LAN remain forbidden; diagnostics and login-plan usage remain disabled with non-loopback binds, and full paths require a loopback bind.

For `/api` and `/api/*`, GET permits absent Origin and absent Sec-Fetch-Site for direct tools. A present Origin must match the admitted HTTP scheme, hostname and effective port, without credentials, path, query or fragment. Null and duplicate origins are rejected. Present Sec-Fetch-Site must be `same-origin` or `none`; conflicting, unknown or duplicate values are rejected. Every POST requires that exact Origin and accepts only absent or `same-origin` Sec-Fetch-Site. Localhost and 127.0.0.1 are separate origins. Static GET routes retain the Host gate but do not apply this API source gate.

Source rejection occurs before route handlers, export admission, settings writes and upstream requests. Errors retain the standard envelope: 400 `INVALID_HOST` / `INVALID_REQUEST_TARGET`, and 403 `INVALID_ORIGIN` / `INVALID_FETCH_METADATA`. Malformed HTTP can be rejected by Node before the application. These headers do not authenticate local programs, detect a proxy that rewrites them, or enable HTTPS tunnel domains. See [local validation](archive/validation/local-host-origin-validation.md).

Errors use `{ "error": { "code", "message", "requestId" } }`. `POST /api/refresh` requires same-origin `Origin` and refreshes only the selected provider; exports are provider-labelled, redacted, and CSV-safe.

## Providers and version

`GET /api/providers` returns `{ providers, version }`. `version` is the running server package version, also shown in the dashboard header. Availability contains no local paths. Dashboard, session, detail, export, diagnostics, refresh, pricing refresh, and deprecated summary routes accept `provider=codex|claude`; omission selects Codex. Unknown providers return `INVALID_PROVIDER`, and a missing sessions root returns `PROVIDER_UNAVAILABLE` without stopping the server.

## Queries, sessions and accounting

Dashboard and session-list requests share range, timezone, search, sorting, pagination, and filters, including `executionType=main|subagent`. Their session rows are summaries only. `GET /api/sessions/:sessionKey` loads bounded, redacted observations on demand. Session keys include provider identity and cannot cross provider boundaries.

Session detail includes exact completeness metadata. `observationCount` counts every adopted observation after the current range and filters. `returnedObservationCount` equals `observations.length`; `observationLimit` uses the server's `DETAIL_OBSERVATION_LIMIT` (default 2000, valid range 1–100000). `observationsTruncated` is true only when fewer observations are returned than adopted. The response retains the first `observationLimit` observations in the existing order. Token and cost totals use every adopted observation in the selected projection, before the response is clipped. An unresolved Session can have zero adopted observations and an incomplete-data warning. Counts do not include rejected or unresolved source records. These fields are additive; detail pagination and an observation table are not included. The drawer displays unknown when an older response has no exact total, rather than using its bounded array length as the total. Clients cannot override the cap with a query parameter.

Model filters select usage observations before aggregation. KPI, model ranks, trend, Session pages, detail, comparison, and exports use the same selected observations. Session `model` remains the legacy metadata label. The additive `models` array lists models in the adopted projection; the client uses that array for Session labels. Model facets include adopted models from the same query without its model selection. Text search matches Session metadata and adopted event models; it does not turn a text match into a model filter.

`pricing.calculationPolicy` and `projection.pricingPolicy` identify `current-rates-all-event-dates-v1`: use the retained current rates for all selected event dates. Rule effectiveFrom values remain in the archived basis as provenance and do not exclude historical usage. This is not a historical billing ledger. CSV adds pricingCalculationPolicy to its scope columns.

`cost.total` is the known token cost for adopted observations when cost.available is true. If billable usage exists but none has a known price, cost.available=false, cost.unavailableReason=unpriced-usage, monetary components are null, and pricingCoverage has ratio=0/partial=true. Trends and model totals follow the same rule. A mixture of priced and unpriced usage retains its known subtotal as a lower bound. Empty usage and confirmed zero-price rates remain numeric zero. With no verified pricing archive, cost.available=false, cost.unavailableReason=pricing-basis, every monetary component is null, and pricingCoverage.available=false/ratio=null/partial=true. Token counts remain available. CSV cost cells are blank and Markdown says unknown. Consumers must handle these nullable amounts rather than convert them to zero. `pricingCoverage` identifies priced and unpriced tokens, unknown models, missing components, unknown modifiers, and `partial`. Claude generic cache-write tokens remain in usage totals. Only a valid 5-minute/1-hour breakdown receives its corresponding write rate; any remainder stays unpriced. If a modifier is unknown, all token components in that observation stay unpriced. Unknown components do not become zero-price components. Budget thresholds still use known cost and show partial-pricing context; unavailable cost budgets have unknown status in the UI.

Session `usageQuality` and `quality.range.usage` contain `incomplete`, `possibleDuplicate`, `cacheWriteInconsistent`, and `reasons`. Reconciliation counters describe the complete matched source Sessions, including excluded observations; they are not counts limited to the selected time interval or model. The tokens and cost are limited to the selected observations. A source Session with unresolved usage may remain visible with zero adopted observations and a quality note. Incomplete and possible-duplicate totals are adopted quantities, not universal lower bounds.

Reconciliation uses provider, explicit Session identity, execution type, and agent identity. SHA-256 of decoded file bytes proves a copy within that scope, including equivalent plain and compressed Codex files. Explicit usage/message event identities prove shared records; turn/context IDs and Session IDs alone do not. Raw cumulative states are versioned before deltas. Same-model turn records are excluded when that execution scope has valid cumulative observations, with an incomplete-data warning rather than a claim of proven coverage. Independent unproven file chains remain present and are marked as possible duplicates.

Codex paginated history uses `history_base.thread_id` and `end_byte_offset` to resolve the last cumulative counter in the referenced decoded file prefix. UTF-8 bytes, CRLF, and compressed files use the same boundary semantics. A fork or continuation subtracts this inherited baseline, not the ancestor's current final total. A prefix with no local counter can inherit its own ancestor's baseline. Same-Session continuation files with a verified link share one summary; forks retain separate Sessions and count only their new usage. Missing, cyclic, over-depth, or unavailable history suppresses the first inherited cumulative value and reports incomplete usage; it does not invent an exact total. Matching counter values alone never prove duplicate requests. Incremental refresh resolves history again from the current file index, without changing retained parsed files.

An explicit `forked_from_id` without a usable history boundary is not sufficient to remove arbitrary ancestor events. Such logs retain adopted usage with incomplete and possible-duplicate warnings; exact fork accounting for that variant remains unsupported.

Claude assistant message IDs also identify copied responses across distinct Session IDs within the same execution type and agent namespace. One adopted response version contributes tokens and cost to one owning Session. New response IDs remain billable, even if their text or token counts match. Existing latest-valid-version and conflict-retention rules apply across these Sessions. Responses without message IDs remain counted with a possible-duplicate warning; request, turn, and content similarities are not proof. Main and distinct subagents remain separate namespaces. Ownership can move to a newer response version; summaries, detail, trend, and exports all use the adopted observations. Raw history metadata and byte offsets remain process-memory-only and are not returned in projections.

Reliable time selects the latest valid event version, with same-file sequence for tied or missing timestamps. Conflicting cross-file versions without reliable order retain a previously confirmed version when available; otherwise they remain unresolved. Same-file order and shared event identities can establish a cumulative chain even with estimated timestamps. An unorderable branch retains the stable canonical chain and reports incomplete data. Confirmed versions, raw normalized usage, and hashes remain in memory and are not returned by the API. They do not retain conversation text.

A partial counter decrease skips that increment and updates the baseline. A full restart is accepted only when all previously positive counters fall without any counter rising, and both positive input/output counters fall or every counter is cleared. A fall in an input-only counter is treated as uncertain. Subsequent valid increments remain countable.

Exports add cost and usage qualifiers. Session CSV adds `selectedModels`, `partialCost`, `usageIncomplete`, `possibleDuplicate`, and `usageNotes`; existing columns remain in order. Trend CSV adds query-wide `usageNotes`; JSON carries full normalized quality; Markdown states partial pricing, incomplete usage, and possible duplication. Phase 4's implemented projection and full matched export rules are specified below. Deprecated summary totals still describe the full adopted snapshot while its Session rows follow the query.

## Calendar ranges and comparison

Time queries retain IANA timezone choices and UTC millisecond instants. Ranges are half-open. `period` is optional for week/month/year only, with formats `YYYY-Www`, `YYYY-M` or `YYYY-MM`, and `YYYY`. The browser pads valid month values to `YYYY-MM`. A supplied ISO week must exist in its week year. Omission selects the current local period. Impossible dates and invalid periods return HTTP 400 `INVALID_RANGE`; they do not normalize or fall back to the current period. `limit` is 1–200, `offset` is 0–1000000; invalid values return HTTP 400 `INVALID_QUERY`. UTC bounds must be safe integers within the JavaScript Date range, and ordered when both are present.

Custom `start`/`end` are local civil times in the selected timezone. Nonexistent and ambiguous times return `INVALID_RANGE`, with guidance to use a precise chart interval or explicit UTC millisecond bounds. `from`/`to` take precedence for their respective boundaries. Valid existing exact chart URLs remain usable through DST folds and reloads. Hourly trend points have separate actual bounds across a fold, and labels include UTC offsets. Half-hour transitions can produce shorter hourly buckets. Calendar boundaries use the earliest instant of a repeated midnight or the first valid instant after a midnight gap.

`comparison` remains null for all-time. Calendar modes compare the prior same calendar unit; completed periods compare both full periods. Unfinished periods compare the same local progress. A missing prior date uses prior period end. Custom and last24h use equal actual duration. Existing comparison `range`, `totals`, and `percentTotalTokens` remain, with additive `available`, `basis` (`calendar|elapsed`), `partial`, `currentRange`, and `currentTotals`. The percentage uses currentTotals, not necessarily the whole selected KPI period. The client shows both intervals and the basis. A captured request clock fixes the progress cutoff within each projection. Guarded continuation requests reuse it through projectionAt.

An unavailable comparison returns `available: false` and a reason: `not-started`, `ambiguous-progress`, `empty-period`, or `invalid-bound`. An ambiguous/nonexistent automatic prior progress does not reject the whole dashboard. No percentage is fabricated. Phase 5's implemented quota reliability rules are specified above.

## Refresh and watchers

Session refresh is transactional. A hard parse/read/worker failure rejects the whole refresh; previously successful index data, usage provenance, and snapshot version remain unchanged. A successful pass admits stable file membership and fingerprints before publication. Files changing during a pass trigger a bounded follow-up, with up to three candidate passes per cache refresh. A failed follow-up never publishes its earlier candidate. Skipped malformed JSONL lines and uncertain observations retain their existing separate quality rules; they do not become hard-file exceptions.

`scan` and `quality.scan` add `maxFiles`, `truncated`, `complete`, `includedFiles`, `omittedFilesAtLeast`, `excluded`, and `verificationDurationMs`. `complete` describes discovered file coverage within the scan, not universal usage correctness. Exactly MAX_FILES admitted files are complete if no additional JSONL is found. Once an extra file is found, coverage is incomplete and omittedFilesAtLeast is 1. Discovery stops there; this is not an exact omitted-file count. Previously indexed files outside a capped selection count as excluded rather than confirmed deleted. A stable uncapped pass counts actual deletion and removes its usage.

`refreshFailure` is null after success or contains normalized code, reason, failedFiles, and checkedAt for the latest failed attempt. `retainedSnapshot` states whether the current response preserves a prior snapshot after that failure. Existing dashboard/list reads can return the retained snapshot with these qualifiers; a missing provider root still follows PROVIDER_UNAVAILABLE. A first scan failure returns 503 rather than a successful empty snapshot. Hard refresh errors use `SESSION_REFRESH_FAILED` and add safe `reason`, `failedFiles`, and `retainedSnapshot` inside the existing error envelope. Reasons do not contain local paths, raw parser messages, or log content.

When AUTO_REFRESH is enabled, each provider owns one watcher, a debounce timer, and one recovery timer. Missing/error watchers retry; a one-second identity check also detects root replacement. In-flight events mark the scan dirty so the final candidate includes a stable follow-up. Unstable-file failures schedule a later retry; other failed-file results remain visible until repair or manual retry. Close clears timers, detaches watchers, stops owned workers, and prevents later publication. This phase updates server snapshots; automatic browser synchronization remains deferred.

## Settings

`GET /api/settings` is loopback-only, reads the current .env file, and returns settings, restartRequired=true, and revision. `POST /api/settings` retains the exact allow-listed settings body and requires same-origin Origin plus `If-Match: "<revision>"`. Missing/malformed versions return 428 SETTINGS_REVISION_REQUIRED; mismatches return 409 SETTINGS_CONFLICT. Every caller must GET a revision before saving; the former unversioned POST behavior is no longer supported. GET and successful POST add writable and writeReason (null for an owner). Startup obtains one cooperative dashboard writer per settings path; other instances keep settings read-only until restart. Non-owner or lost-owner writes return 409 SETTINGS_READ_ONLY. Owner PID, host, generation and lock path are not returned. Responses describe the committed settings and new revision; runtime configuration applies after restart. Saves serialize within the process, validate ownership inside queued writes and use exclusive UUID temporary files. External edits detected before rename reject the save. A dashboard-only lease cannot exclude an independent editor in the final check-to-rename interval; stop the owner before external edits. Normal signal shutdown and failed listen release the owned generation. Startup automatically retires a valid same-host lease only when the owner PID is confirmed absent and rechecked inside guarded retirement, then competes for one new writer lease. Active, foreign, damaged, busy, permission-denied or unknown ownership remains read-only. Running readers never take over. Explicit node server.mjs --unlock-settings recovery remains available under the same absent-owner guard. This command runs before pricing, scanning or listening. The client preserves rejected edits and asks before discarding them to reload. Settings admission requires both real socket endpoints to be loopback and the validated URL to name a loopback address or localhost. Wildcard binds therefore permit local settings administration, while LAN connections and the 0.0.0.0 URL return 403 SETTINGS_DISABLED. Forwarded headers cannot grant admission. Every bind participates in the same startup writer lease.

## Login-plan quota

`GET /api/account-usage` returns a loopback-only, 60-second cached view of the selected provider's login-plan quota windows. `POST /api/account-usage/refresh` requires a same-origin `Origin` and bypasses that cache. Responses contain normalized provider, status, reason, plan type, fetchedAt (last success), checkedAt (last attempt), percentages, duration, and reset time. Status is available, stale, or unavailable. Network, rate-limit, and service failures retain same-login successful windows as stale; failed windows past their reported reset have null percentages and resetExpired=true. Missing resets remain unknown. Null/empty/boolean/out-of-range percentages are not zero; measured numeric zero is supported. Authentication, known Claude token expiry, missing/invalid/changed credentials and unsupported formats clear former quota. Unavailable has fetchedAt=null and windows=[]. Cache checks and response publication verify a server-only credential-file digest. Claude credentials are read-only: no OAuth refresh request or credential-file write occurs. Expired/rejected login returns auth-expired; update it in the CLI, then recheck. A detected file replacement returns credentials-changed. Known expiry is checked before cache reuse; a still-valid near-expiry token can be used. No response contains tokens, digests, account identifiers, email addresses, or credential paths. Remote mode returns `ACCOUNT_USAGE_DISABLED`.

## Updates

`POST /api/update` performs the manual latest stable release check with an anonymous server-side GET to the configured public GitHub repository. No request body is allowed: nonzero Content-Length or any Transfer-Encoding returns 413 `BODY_NOT_ALLOWED`. Direct tools must supply the exact Origin and an empty, non-chunked request. `GET /api/update` returns 405 `METHOD_NOT_ALLOWED` with `Allow: POST` and makes no upstream request; callers must migrate to POST. Missing repository configuration defaults to `ethan-devlab/ai-token-dashboard`; an explicit blank disables checks and a custom repository takes precedence.

## Diagnostics and shutdown

`GET /api/diagnostics` adds `lifecycle: { available, lastError, lastRecordedAt }`. `lastRecordedAt` is the UTC timestamp of the last complete record, or null. `lastError` is null or a restricted journal code (`unsafe-directory`, `unsafe-file`, `open-failed`, `write-failed`, `close-failed`). A journal failure latches unavailable for that process; it does not block analysis or settings saves. This additive object contains no PID, run identity, file name/path or record contents. Existing loopback and source guards still apply.

During graceful shutdown, a connected request not yet admitted to route work receives 503 `SERVER_STOPPING` in the existing error envelope after Host/Origin validation. New connections stop, active exports are interrupted, and admitted asynchronous work is drained even if its client has disconnected. SIGINT, SIGTERM and SIGHUP share one 30-second deadline; repeated signals do not extend it. Unsafe/unreleased locks remain after timeout or failed cleanup. No lifecycle history, deletion or automatic lock recovery API is added.

## Projection and complete exports

Dashboard/list/detail add `projection`: key (SHA-256), server epoch, provider, snapshotVersion, pricingRevision, pricingAvailable, normalized query and `at` (UTC milliseconds). `query` contains range, q, sort and sorted filter sets. Offset/limit are excluded from identity. The pricing revision is the archive's canonical calculation-basis hash, including effective rules/rates/modifiers, but excluding checkedAt and observation-date updatedAt. pricingAvailable prevents an unknown-cost projection from mixing with recovered costs under the same basis. The epoch prevents accidental equality after server restart. The key is a consistency guard, not a credential.

List/detail/export accept optional `projection=<key>&projectionAt=<at>`. The server resolves ranges/comparison with the captured clock and verifies current snapshot/pricing/query identity before sending data. Invalid keys/clocks return 400; a mismatch returns 409 `PROJECTION_CONFLICT` in the existing envelope. List and detail do not retain old snapshots. A prepared export retains its verified projection until release. Omitting the guard keeps the latest projection behavior. Manual refresh returns a complete new projection.

The shipped client uses guarded page/detail/export requests. Equal projections merge only page fields and the latest refreshFailure/retainedSnapshot qualifiers in scan and quality.scan. A failed refresh can change these qualifiers without replacing the usage snapshot; pagination must retain that warning. KPI, charts, models, pricing and other scan/quality data remain the displayed projection. Conflict clears cache, returns to page one, closes detail, reloads the complete dashboard and shows a localized notice. Export does not automatically retry or download after conflict. Browser polling remains disabled. An obsolete response or error cannot replace the current projection.

All export formats represent all matching Sessions/observations under the query, independent of page offset and limit. Existing limit/offset validation still applies. CSV appends range, search/filter/sort, identity, clock, count, scope and pricing basis columns; existing columns and quoting/redaction remain. JSON adds metadata; Markdown lists exact UTC bounds (inclusive start/exclusive end), query and pricing basis. JSON/Markdown retain partial-cost and usage-quality qualifiers. A compact URI-encoded JSON `X-Export-Scope` header contains key, snapshot/revision, bounds, matched count and scope. Generation is unpaged and streamed with response backpressure and exact UTF-8 Content-Length. The former 32 MiB cap and EXPORT_TOO_LARGE response are removed. Both CSV formats append `scanComplete`, `queryUsageIncomplete`, `queryPossibleDuplicate`, `queryPartialPricing` and `recordType` after the previous columns. Normal rows use `recordType=data`. A CSV with no data rows contains one `recordType=metadata` row, with provider, scope, filters, bounds, versions, pricing basis and quality qualifiers. Session/bucket identities, Token measurements and cost cells in this row are blank. Consumers must exclude metadata rows from data counts and sums. This replaces the old header-only empty CSV behavior; existing data columns stay in their previous order. JSON/Markdown behavior stays unchanged.

## Read-only pricing archives

All selected events, including historical ones, use current-basis estimation. Dashboard/list pricing adds policy=current-basis, revision, complete basis and archive status. JSON/Markdown report metadata carries the complete basis, including matching rules/effectiveFrom and Claude multipliers. CSV adds pricingArchived before recordType and references pricingRevision. No historical effective-rate ledger, old-basis switcher or official bill reconstruction is provided.

GET /api/pricing/versions accepts provider (default codex), offset (0–1,000,000) and limit (1–100, default 100). It returns provider, items, total, offset, limit, hasNext and current archive status. Items are sorted lexically by revision and contain revision, status=verified, firstArchivedAt, lastCheckedAt, origin and metadataError; an invalid entry returns only revision/status=invalid. List reads are limited to the selected page; directory enumeration covers all stored filenames. Unknown providers and malformed pagination return 400.

GET /api/pricing/versions/:revision requires 64 lowercase hexadecimal characters and selects only that provider's archive. It returns version=1, provider, revision, basis, firstArchivedAt, lastCheckedAt, metadataError and origin (bundled/cache/refresh). Missing revisions return 404 PRICING_REVISION_NOT_FOUND; malformed revisions return 400 INVALID_QUERY; invalid or inaccessible records return 503 ARCHIVE_INVALID. Responses omit local paths and raw filesystem errors. A record is at most 1 MiB. The complete canonical basis must reconstruct to the same hash. These routes are read-only and provide no activation/deletion endpoint.

Archive records remain under .pricing-archive/provider without automatic deletion. firstArchivedAt is actual archive time, not an official rate effective date. Explicit repair can restore the first time from a previously verified record; otherwise a recreated record uses its actual new archive time. origin identifies that archived record. Optional check metadata is separate: missing or invalid check data gives an unknown time; invalid data adds metadataError=metadata. It does not invalidate the calculation basis. Current pricing.checkedAt and refresh.lastCheckedAt only expose verified archive check time. A failed metadata write stays visible in the publication until a verified metadata publication or explicit repair; it does not claim a new archived check.

## Pricing ownership, publication and repair

One pricing writer is acquired before initialization for the entire app directory, independently of settings ownership. Startup uses the same guarded automatic recovery for a valid confirmed absent same-host owner; active, foreign, damaged, busy, permission-denied or uncertain ownership remains read-only. It owns both Provider caches, basis records and check metadata. Additional processes remain read-only until restart: no initialization writes, automatic source requests or recovery writes. Normal shutdown waits for admitted pricing work before releasing its generation. Failed listen also releases its own generation. Lost ownership blocks later file mutations and source requests. Owner PID, host, generation and local lock path are not returned by HTTP.

Version-1 cache records are current publications. Their Provider/source, complete calculation basis, optional recorded digest and corresponding archive must agree. A candidate is archived before publication; publication is atomically renamed before activation. A failed write retains the previous committed basis. Archive-only candidates are not selected at restart. A missing/damaged existing publication leaves Tokens usable and cost unknown; no archive scan chooses a current version. Only an empty Provider store permits writer initialization from bundled rates. A reader waits for a valid publication.

Every dashboard, Session page/detail, deprecated summary, reparse response and export preparation revalidates its active basis on disk. A failed active verification changes pricingAvailable and invalidates old projection guards. Read requests do not repair. A reader can retain a valid older published basis until explicit load. Already admitted native downloads are not revalidated or rewritten at transfer time.

Same-origin, body-free operations accept the usual Provider/query fields and return a complete dashboard projection with pricingUpdate.action:

| Route | Access and behavior |
| --- | --- |
| POST /api/pricing/refresh | Writer only; fetch, validate, archive and publish the selected Provider. Successful changedModels lists changed rates. Manual refresh remains available when a daily automatic check is skipped |
| POST /api/pricing/load | Reader or writer; validate the latest publication before replacing the active basis. Failure retains an older basis only if its archive remains valid |
| POST /api/pricing/repair | Writer only; repair current storage from this process's verified retained basis or freshly validated fixed-source pricing. No path or historical revision input is accepted |

pricing.refresh adds writable/writeReason, publicationError, metadataError and persistenceError. archive retains available, revision, firstArchivedAt, lastCheckedAt, origin and error. Verification, publication, metadata and ownership states remain separate. Failed source attempts add lastError without exposing filesystem messages. Initialization and normal queries do not repair damaged files.

Repair quarantines invalid publication/basis/check files under unique app-local names, preserves their bytes and never overwrites a valid basis. A record that becomes valid during quarantine is restored without replacement and stops repair with a conflict. If a damaged basis requires restoration, a persistent cache-adjacent .repairing marker blocks affected revisions until publication and marker release succeed. Readers and restarts see unknown cost while that repair is incomplete. A valid older retained revision outside the marker can remain usable. A pending prepared download retains its admitted content. Quarantine and repair markers are not historical version activation APIs.

Failures use the existing envelope: 409 PRICING_READ_ONLY, 409 PRICING_REPAIR_CONFLICT, 503 PRICING_LOAD_FAILED, and 502 PRICING_PUBLICATION_FAILED / PRICING_ARCHIVE_FAILED / PRICING_REFRESH_FAILED / PRICING_REPAIR_FAILED. Invalid Origin remains 403 and nonempty declared bodies remain rejected. Detailed public failure state is available on the next full dashboard response. No force recovery is exposed through HTTP.

node server.mjs --unlock-pricing runs before services, scanning or listening. It only removes a guarded same-host lock whose owner PID is confirmed absent. Active/unknown/foreign/malformed ownership is refused. A reader must restart to acquire the released write lease. These rules coordinate cooperating dashboard processes; external file editors must stop the writer. Process interruption/restart is tested; power-loss durability, live upstream contracts and Windows storage behavior remain unverified. See [the delivery record](archive/validation/pricing-ownership-recovery-validation.md).

## Native streamed download lifecycle

`POST /api/export/prepare` requires same-origin Origin, the normal query/format and both projection guards. It returns `{ downloadUrl, expiresAt, byteLength, fileName }`. A stale displayed projection returns 409 PROJECTION_CONFLICT before handoff. The client reloads the complete page and waits for another Download action. Successful preparation pins the query, snapshot and pricing basis. `GET /api/export/download/:ticket` streams that plan even if another query or refresh has since changed current data. The ticket is unpredictable, memory-only, one-use and valid for two minutes; expired or used tickets return 410 EXPORT_EXPIRED. Invalid ticket syntax returns 400 INVALID_EXPORT_TICKET.

`GET /api/export` remains available for direct clients, with optional projection guards and streamed output. Direct and prepared downloads share one process-wide slot, including both Providers. Another request returns 429 EXPORT_BUSY immediately; no queue is created. All routes preserve Host, CSP, no-store, redaction, filename and scope headers. Tickets are not logged or persisted.

The transport writes bounded buffers and waits for the write callback and backpressure drain before reuse. It counts bytes before sending headers without allocating the complete encoded file. Preparation retains the selected projection and required report rows; uncapped output is not a guarantee of unlimited input capacity. A transfer stops after 60 seconds without transport progress or 30 minutes total. Completion, disconnect, failure, deadlines and shutdown release the slot and retained plan. Errors after headers close the connection; they never append an error envelope to the file. Content-Length lets a browser detect incomplete bytes.

The shipped UI uses the browser download manager and states only that handoff occurred. The browser owns Save, Cancel and partial files. Interruptions restart through a new Dashboard download; explicit Range requests return 416 RANGE_NOT_SUPPORTED. No Range resume is advertised. Leaving the page or changing Provider does not cancel a transfer already handed off. An obsolete preparation cannot trigger handoff or publish errors. A lost preparation response can hold a ready slot until its two-minute expiry. See [performance and desktop validation](archive/validation/query-export-performance-validation.md).
