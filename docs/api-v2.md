# API v2

`GET /api/providers` lists Codex and Claude availability without local paths. Dashboard, session, detail, export, diagnostics, refresh, pricing refresh, and deprecated summary routes accept `provider=codex|claude`; omission selects Codex. Unknown providers return `INVALID_PROVIDER`, and a missing sessions root returns `PROVIDER_UNAVAILABLE` without stopping the server.

`GET /api/account-usage` returns a loopback-only, 60-second cached view of the selected provider's login-plan quota windows. `POST /api/account-usage/refresh` requires a same-origin `Origin` and bypasses that cache. Both responses contain only normalized provider, availability reason, plan type, checked time, used/remaining percentages, window duration, and reset time. They never contain tokens, account identifiers, email addresses, or credential paths. Remote mode returns `ACCOUNT_USAGE_DISABLED`.

Dashboard and session-list requests share range, timezone, search, sorting, pagination, and filters, including `executionType=main|subagent`. Their session rows are summaries only. `GET /api/sessions/:sessionKey` loads bounded, redacted observations on demand. Session keys include provider identity and cannot cross provider boundaries.

Model filters select usage observations before aggregation. KPI, model ranks, trend, Session pages, detail, comparison, and exports use the same selected observations. Session `model` remains the legacy metadata label. The additive `models` array lists models in the adopted projection; the client uses that array for Session labels. Model facets include adopted models from the same query without its model selection. Text search matches Session metadata and adopted event models; it does not turn a text match into a model filter.

`cost.total` is the known token cost for adopted observations. `pricingCoverage` identifies priced and unpriced tokens, unknown models, missing components, unknown modifiers, and `partial`. Claude generic cache-write tokens remain in usage totals. Only a valid 5-minute/1-hour breakdown receives its corresponding write rate; any remainder stays unpriced. If a modifier is unknown, all token components in that observation stay unpriced. Unknown components do not become zero-price components. Budget thresholds still use known cost and show partial-pricing context.

Session `usageQuality` and `quality.range.usage` contain `incomplete`, `possibleDuplicate`, `cacheWriteInconsistent`, and `reasons`. Reconciliation counters describe the complete matched source Sessions, including excluded observations; they are not counts limited to the selected time interval or model. The tokens and cost are limited to the selected observations. A source Session with unresolved usage may remain visible with zero adopted observations and a quality note. Incomplete and possible-duplicate totals are adopted quantities, not universal lower bounds.

Reconciliation uses provider, explicit Session identity, execution type, and agent identity. SHA-256 of exact file bytes proves a copy within that scope. Explicit usage/message event identities prove shared records; turn/context IDs and Session IDs alone do not. Raw cumulative states are versioned before deltas. Same-model turn records are excluded when that execution scope has valid cumulative observations, with an incomplete-data warning rather than a claim of proven coverage. Independent unproven file chains remain present and are marked as possible duplicates.

Reliable time selects the latest valid event version, with same-file sequence for tied or missing timestamps. Conflicting cross-file versions without reliable order retain a previously confirmed version when available; otherwise they remain unresolved. Same-file order and shared event identities can establish a cumulative chain even with estimated timestamps. An unorderable branch retains the stable canonical chain and reports incomplete data. Confirmed versions, raw normalized usage, and hashes remain in memory and are not returned by the API. They do not retain conversation text.

A partial counter decrease skips that increment and updates the baseline. A full restart is accepted only when all previously positive counters fall without any counter rising, and both positive input/output counters fall or every counter is cleared. A fall in an input-only counter is treated as uncertain. Subsequent valid increments remain countable.

Exports add cost and usage qualifiers. Session CSV adds `selectedModels`, `partialCost`, `usageIncomplete`, `possibleDuplicate`, and `usageNotes`; existing columns remain in order. Trend CSV adds query-wide `usageNotes`; JSON carries full normalized quality; Markdown states partial pricing, incomplete usage, and possible duplication. Pagination and snapshot export changes remain deferred to Phase 4. Deprecated summary totals still describe the full adopted snapshot while its Session rows follow the query.

Time queries retain IANA timezone choices and UTC millisecond instants. Ranges are half-open. `period` is optional for week/month/year only, with formats `YYYY-Www`, `YYYY-MM`, and `YYYY`. A supplied ISO week must exist in its week year. Omission selects the current local period. Invalid dates and periods return HTTP 400 `INVALID_RANGE`; they do not normalize or fall back to the current period. `limit` is 1–200, `offset` is 0–1000000; invalid values return HTTP 400 `INVALID_QUERY`. UTC bounds must be safe integers within the JavaScript Date range, and ordered when both are present.

Custom `start`/`end` are local civil times in the selected timezone. Nonexistent and ambiguous times return `INVALID_RANGE`, with guidance to use a precise chart interval or explicit UTC millisecond bounds. `from`/`to` take precedence for their respective boundaries. Valid existing exact chart URLs remain usable through DST folds and reloads. Hourly trend points have separate actual bounds across a fold, and labels include UTC offsets. Half-hour transitions can produce shorter hourly buckets. Calendar boundaries use the earliest instant of a repeated midnight or the first valid instant after a midnight gap.

`comparison` remains null for all-time. Calendar modes compare the prior same calendar unit; completed periods compare both full periods. Unfinished periods compare the same local progress. A missing prior date uses prior period end. Custom and last24h use equal actual duration. Existing comparison `range`, `totals`, and `percentTotalTokens` remain, with additive `available`, `basis` (`calendar|elapsed`), `partial`, `currentRange`, and `currentTotals`. The percentage uses currentTotals, not necessarily the whole selected KPI period. The client shows both intervals and the basis. A captured request clock fixes the progress cutoff within each projection. It is not a client-controlled query parameter.

An unavailable comparison returns `available: false` and a reason: `not-started`, `ambiguous-progress`, `empty-period`, or `invalid-bound`. An ambiguous/nonexistent automatic prior progress does not reject the whole dashboard. No percentage is fabricated. Quota, refresh rollback, watcher recovery, projection snapshot identity, and complete exports remain later-phase work.

Errors use `{ "error": { "code", "message", "requestId" } }`. `POST /api/refresh` requires same-origin `Origin` and refreshes only the selected provider; exports are provider-labelled, redacted, and CSV-safe.
