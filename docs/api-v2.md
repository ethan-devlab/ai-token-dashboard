# API v2

`GET /api/providers` lists Codex and Claude availability without local paths. Dashboard, session, detail, export, diagnostics, refresh, pricing refresh, and deprecated summary routes accept `provider=codex|claude`; omission selects Codex. Unknown providers return `INVALID_PROVIDER`, and a missing sessions root returns `PROVIDER_UNAVAILABLE` without stopping the server.

`GET /api/account-usage` returns a loopback-only, 60-second cached view of the selected provider's login-plan quota windows. `POST /api/account-usage/refresh` requires a same-origin `Origin` and bypasses that cache. Responses contain normalized provider, status, reason, plan type, fetchedAt (last success), checkedAt (last attempt), percentages, duration, and reset time. Status is available, stale, or unavailable. Network, rate-limit, and service failures retain same-login successful windows as stale; failed windows past their reported reset have null percentages and resetExpired=true. Missing resets remain unknown. Null/empty/boolean/out-of-range percentages are not zero; measured numeric zero is supported. Authentication, missing/invalid/changed credentials, unsafe rotation, and unsupported formats clear former quota. Unavailable has fetchedAt=null and windows=[]. Cache checks and response publication verify a server-only credential-file digest. A detected concurrent Claude login replacement aborts rotation and returns credentials-changed; the user can check again. No response contains tokens, digests, account identifiers, email addresses, or credential paths. Remote mode returns `ACCOUNT_USAGE_DISABLED`.

`GET /api/settings` is loopback-only, reads the current .env file, and returns settings, restartRequired=true, and revision. `POST /api/settings` retains the exact allow-listed settings body and requires same-origin Origin plus `If-Match: "<revision>"`. Missing/malformed versions return 428 SETTINGS_REVISION_REQUIRED; mismatches return 409 SETTINGS_CONFLICT. Every caller must GET a revision before saving; the former unversioned POST behavior is no longer supported. Responses describe the committed settings and new revision; runtime configuration applies after restart. Saves serialize within the process and use exclusive UUID temporary files. External edits detected before rename reject the save. The client preserves rejected edits and asks before discarding them to reload. Remote mode remains SETTINGS_DISABLED.

Dashboard and session-list requests share range, timezone, search, sorting, pagination, and filters, including `executionType=main|subagent`. Their session rows are summaries only. `GET /api/sessions/:sessionKey` loads bounded, redacted observations on demand. Session keys include provider identity and cannot cross provider boundaries.

Model filters select usage observations before aggregation. KPI, model ranks, trend, Session pages, detail, comparison, and exports use the same selected observations. Session `model` remains the legacy metadata label. The additive `models` array lists models in the adopted projection; the client uses that array for Session labels. Model facets include adopted models from the same query without its model selection. Text search matches Session metadata and adopted event models; it does not turn a text match into a model filter.

`cost.total` is the known token cost for adopted observations. `pricingCoverage` identifies priced and unpriced tokens, unknown models, missing components, unknown modifiers, and `partial`. Claude generic cache-write tokens remain in usage totals. Only a valid 5-minute/1-hour breakdown receives its corresponding write rate; any remainder stays unpriced. If a modifier is unknown, all token components in that observation stay unpriced. Unknown components do not become zero-price components. Budget thresholds still use known cost and show partial-pricing context.

Session `usageQuality` and `quality.range.usage` contain `incomplete`, `possibleDuplicate`, `cacheWriteInconsistent`, and `reasons`. Reconciliation counters describe the complete matched source Sessions, including excluded observations; they are not counts limited to the selected time interval or model. The tokens and cost are limited to the selected observations. A source Session with unresolved usage may remain visible with zero adopted observations and a quality note. Incomplete and possible-duplicate totals are adopted quantities, not universal lower bounds.

Reconciliation uses provider, explicit Session identity, execution type, and agent identity. SHA-256 of exact file bytes proves a copy within that scope. Explicit usage/message event identities prove shared records; turn/context IDs and Session IDs alone do not. Raw cumulative states are versioned before deltas. Same-model turn records are excluded when that execution scope has valid cumulative observations, with an incomplete-data warning rather than a claim of proven coverage. Independent unproven file chains remain present and are marked as possible duplicates.

Reliable time selects the latest valid event version, with same-file sequence for tied or missing timestamps. Conflicting cross-file versions without reliable order retain a previously confirmed version when available; otherwise they remain unresolved. Same-file order and shared event identities can establish a cumulative chain even with estimated timestamps. An unorderable branch retains the stable canonical chain and reports incomplete data. Confirmed versions, raw normalized usage, and hashes remain in memory and are not returned by the API. They do not retain conversation text.

A partial counter decrease skips that increment and updates the baseline. A full restart is accepted only when all previously positive counters fall without any counter rising, and both positive input/output counters fall or every counter is cleared. A fall in an input-only counter is treated as uncertain. Subsequent valid increments remain countable.

Exports add cost and usage qualifiers. Session CSV adds `selectedModels`, `partialCost`, `usageIncomplete`, `possibleDuplicate`, and `usageNotes`; existing columns remain in order. Trend CSV adds query-wide `usageNotes`; JSON carries full normalized quality; Markdown states partial pricing, incomplete usage, and possible duplication. Pagination and snapshot export changes remain deferred to Phase 4. Deprecated summary totals still describe the full adopted snapshot while its Session rows follow the query.

Time queries retain IANA timezone choices and UTC millisecond instants. Ranges are half-open. `period` is optional for week/month/year only, with formats `YYYY-Www`, `YYYY-MM`, and `YYYY`. A supplied ISO week must exist in its week year. Omission selects the current local period. Invalid dates and periods return HTTP 400 `INVALID_RANGE`; they do not normalize or fall back to the current period. `limit` is 1–200, `offset` is 0–1000000; invalid values return HTTP 400 `INVALID_QUERY`. UTC bounds must be safe integers within the JavaScript Date range, and ordered when both are present.

Custom `start`/`end` are local civil times in the selected timezone. Nonexistent and ambiguous times return `INVALID_RANGE`, with guidance to use a precise chart interval or explicit UTC millisecond bounds. `from`/`to` take precedence for their respective boundaries. Valid existing exact chart URLs remain usable through DST folds and reloads. Hourly trend points have separate actual bounds across a fold, and labels include UTC offsets. Half-hour transitions can produce shorter hourly buckets. Calendar boundaries use the earliest instant of a repeated midnight or the first valid instant after a midnight gap.

`comparison` remains null for all-time. Calendar modes compare the prior same calendar unit; completed periods compare both full periods. Unfinished periods compare the same local progress. A missing prior date uses prior period end. Custom and last24h use equal actual duration. Existing comparison `range`, `totals`, and `percentTotalTokens` remain, with additive `available`, `basis` (`calendar|elapsed`), `partial`, `currentRange`, and `currentTotals`. The percentage uses currentTotals, not necessarily the whole selected KPI period. The client shows both intervals and the basis. A captured request clock fixes the progress cutoff within each projection. Guarded continuation requests reuse it through projectionAt.

An unavailable comparison returns `available: false` and a reason: `not-started`, `ambiguous-progress`, `empty-period`, or `invalid-bound`. An ambiguous/nonexistent automatic prior progress does not reject the whole dashboard. No percentage is fabricated. Quota reliability remains Phase 5 work.

Session refresh is transactional. A hard parse/read/worker failure rejects the whole refresh; previously successful index data, usage provenance, and snapshot version remain unchanged. A successful pass admits stable file membership and fingerprints before publication. Files changing during a pass trigger a bounded follow-up, with up to three candidate passes per cache refresh. A failed follow-up never publishes its earlier candidate. Skipped malformed JSONL lines and uncertain observations retain their existing separate quality rules; they do not become hard-file exceptions.

`scan` and `quality.scan` add `maxFiles`, `truncated`, `complete`, `includedFiles`, `omittedFilesAtLeast`, `excluded`, and `verificationDurationMs`. `complete` describes discovered file coverage within the scan, not universal usage correctness. Exactly MAX_FILES admitted files are complete if no additional JSONL is found. Once an extra file is found, coverage is incomplete and omittedFilesAtLeast is 1. Discovery stops there; this is not an exact omitted-file count. Previously indexed files outside a capped selection count as excluded rather than confirmed deleted. A stable uncapped pass counts actual deletion and removes its usage.

`refreshFailure` is null after success or contains normalized code, reason, failedFiles, and checkedAt for the latest failed attempt. `retainedSnapshot` states whether the current response preserves a prior snapshot after that failure. Existing dashboard/list reads can return the retained snapshot with these qualifiers; a missing provider root still follows PROVIDER_UNAVAILABLE. A first scan failure returns 503 rather than a successful empty snapshot. Hard refresh errors use `SESSION_REFRESH_FAILED` and add safe `reason`, `failedFiles`, and `retainedSnapshot` inside the existing error envelope. Reasons do not contain local paths, raw parser messages, or log content.

When AUTO_REFRESH is enabled, each provider owns one watcher, a debounce timer, and one recovery timer. Missing/error watchers retry; a one-second identity check also detects root replacement. In-flight events mark the scan dirty so the final candidate includes a stable follow-up. Unstable-file failures schedule a later retry; other failed-file results remain visible until repair or manual retry. Close clears timers, detaches watchers, stops owned workers, and prevents later publication. This phase updates server snapshots; automatic browser synchronization remains deferred.

Errors use `{ "error": { "code", "message", "requestId" } }`. `POST /api/refresh` requires same-origin `Origin` and refreshes only the selected provider; exports are provider-labelled, redacted, and CSV-safe.

## Projection and complete exports

Dashboard/list/detail add `projection`: key (SHA-256), server epoch, provider, snapshotVersion, pricingRevision, normalized query and `at` (UTC milliseconds). `query` contains range, q, sort and sorted filter sets. Offset/limit are excluded from identity. The pricing revision covers the calculation basis, including effective rules/rates/modifiers, but excludes check-only timestamps. The epoch prevents accidental equality after server restart. The key is a consistency guard, not a credential.

List/detail/export accept optional `projection=<key>&projectionAt=<at>`. The server resolves ranges/comparison with the captured clock and verifies current snapshot/pricing/query identity before sending data. Invalid keys/clocks return 400; a mismatch returns 409 `PROJECTION_CONFLICT` in the existing envelope. No old snapshot is retained for this API. Omitting the guard keeps the latest projection behavior. Manual refresh returns a complete new projection.

The shipped client uses guarded page/detail/export requests. Equal projections merge only page fields and the latest refreshFailure/retainedSnapshot qualifiers in scan and quality.scan. A failed refresh can change these qualifiers without replacing the usage snapshot; pagination must retain that warning. KPI, charts, models, pricing and other scan/quality data remain the displayed projection. Conflict clears cache, returns to page one, closes detail, reloads the complete dashboard and shows a localized notice. Export does not automatically retry or download after conflict. Browser polling remains disabled. An obsolete response or error cannot replace the current projection.

All export formats represent all matching Sessions/observations under the query, independent of page offset and limit. Existing limit/offset validation still applies. CSV appends range, search/filter/sort, identity, clock, count, scope and pricing basis columns; existing columns and quoting/redaction remain. JSON adds metadata; Markdown lists exact UTC bounds (inclusive start/exclusive end), query and pricing basis. JSON/Markdown retain partial-cost and usage-quality qualifiers. A compact URI-encoded JSON `X-Export-Scope` header contains key, snapshot/revision, bounds, matched count and scope. Bodies over 32 MiB return 413 `EXPORT_TOO_LARGE`; no partial file is sent. Generation is unpaged and buffered, not streaming. Q21 confirms typed empty-result metadata. Both CSV formats append `scanComplete`, `queryUsageIncomplete`, `queryPossibleDuplicate`, `queryPartialPricing` and `recordType` after the previous columns. Normal rows use `recordType=data`. A CSV with no data rows contains one `recordType=metadata` row, with provider, scope, filters, bounds, versions, pricing basis and quality qualifiers. Session/bucket identities, Token measurements and cost cells in this row are blank. Consumers must exclude metadata rows from data counts and sums. This replaces the old header-only empty CSV behavior; existing data columns stay in their previous order. JSON/Markdown behavior stays unchanged.
