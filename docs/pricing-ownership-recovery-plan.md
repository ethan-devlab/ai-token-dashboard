# Pricing ownership and recovery plan

Date: 2026-10-01 (Asia/Taipei). Status: implemented after user authorization; see [delivery validation](pricing-ownership-recovery-validation.md). Q51–Q60 remain the selected policy. Source checkpoint: 348a8ba. This phase addresses R02 from [the functional inventory](functional-status-inventory.md). Existing Q28–Q33 current-basis, archive-before-activation, read-only history and permanent retention remain. Q40–Q50 query/export behavior and targets remain.

## Confirmed decisions

| Decision | Policy |
| --- | --- |
| Q51 | One pricing writer per app directory owns Codex and Claude cache, archive and check metadata. Pricing ownership is independent of settings ownership. Other processes only read; they do not fetch new rates or write any pricing files |
| Q52 | A read-only process has an explicit action to load the latest published basis. Validate it before changing active pricing, then reload the complete page. On failure retain the verified version and show the failure. No historical version switcher or automatic synchronization |
| Q53 | A new basis activates only after successful archive and current-publication persistence. If publication fails, retain the previous published basis and report failure |
| Q54 | Missing/corrupt existing publication state does not select an arbitrary archived version. Preserve Token analysis and make cost unknown until an explicit writer refresh succeeds. A genuinely empty initial state is decided separately |
| Q55 | Revalidate the active basis before each cost response or export preparation. Failure makes cost unknown for new requests with a clear reason; reads do not repair files. An already started export keeps its Q47 admitted snapshot |
| Q56 | Verified basis and publication permit pricing even when check metadata fails. Expose metadata failure; unknown/untrusted check times are not presented as archived success |
| Q57 | With no prior publication or archive records for a Provider, its writer seals and publishes bundled pricing before enabling cost. Failure leaves cost unknown. Readers never create initial files |
| Q58 | Pricing ownership follows the settings recovery policy through its own lock and explicit unlock command: startup-fixed access, normal release, read-only additional processes, no background takeover, same-host confirmed-dead-owner recovery only |
| Q59 | This phase verifies process interruption and restart recovery at publication boundaries. Power-loss, hardware durability and cross-platform storage certification remain unverified |
| Q60 | Add restricted explicit manual repair for the pricing writer. Use only newly fetched/validated complete pricing or the process's previously verified complete basis. Preserve damaged records in quarantine, never replace a valid basis, and enable cost only after repair and publication succeed |

Q53 tightens activation from archive success to archive plus publication success. Q56 separates auxiliary metadata from calculation validity. Q60 permits explicit recovery of invalid records; it does not permit modifying a valid immutable basis or choosing an arbitrary historical version. The prior retained-basis offline recovery remains possible through an explicit writer action when a complete previously verified basis exists; an unknown startup state must obtain a validated basis before publication.

## Current evidence

Current `server/pricing-refresh.mjs` publishes a new basis to the immutable archive, activates it in memory, then replaces the cache. A persistence error does not undo activation. Every process can initialize archives, write check metadata, persist automatic attempt state and replace the cache after a failed request. `server/pricing-archive.mjs` publishes basis records exclusively, but check metadata uses read-then-rename without shared ownership. `current()` retains archive availability from prior validation; it does not read the active basis record again.

An isolated in-process reproduction used two independent pricing-service instances with the same disposable cache/archive paths and only synthetic fetch implementations. Both loaded bundled pricing; A then published doubled gpt-5.5 input price. B's later offline refresh persisted its older basis. A retained the new revision in memory, while a new instance loaded the older cached revision even though both basis records were archived. Removing A's active basis record in this disposable root left A.current().archive.available=true; archive.get rejected that missing record. The temporary root was removed. This proves the service publication/revalidation boundaries, not a timed two-OS-process race or power-loss test.

## Implementation boundaries for confirmed policies

1. Add a pricing-specific owner in `server/pricing-owner.mjs` with the proven canonical-path, owner generation, same-host/PID and guarded retirement patterns from `server/settings-owner.mjs`. Keep settings ownership behavior unchanged. Acquire pricing ownership before service initialization on loopback and supported remote bindings. It covers both Provider stores in this app directory. Read-only instances can still serve analytics and exports. Lost/uncertain ownership blocks all pricing writes, including initialization, automatic attempt state, metadata and repair. Normal close/listen failure releases the acquired generation; recovery does not fetch, parse Sessions or modify prices.
2. Own `server/pricing-refresh.mjs`, `server/claude-pricing-refresh.mjs` and `server/pricing-archive.mjs`. Serialize initialization/refresh/load and publication operations for each Provider before any awaited persistence. Stage a candidate separately from committed pricing. Publish its verified immutable basis, then atomically replace the current publication/cache, then activate it. Automatic-attempt and error metadata must never publish an older basis after a newer commit. The two Provider stores remain independent under one writer; no cross-Provider all-or-nothing price transaction is implied.
3. Use the current cache as the explicit active publication source; keep existing version-1 cache compatibility and verify its Provider/source, complete canonical basis, digest and corresponding immutable archive. Do not choose the last archive by filename, mtime or check timestamp. A new valid archive that cannot be published remains retained but inactive. Readers cannot create directories, seal bundled/cache rates, persist check state, repair files or call upstream pricing fetch. An existing cache without its valid archive remains unverified until an explicit writer recovery succeeds.
4. Separate immutable basis validation from optional check metadata. Missing/corrupt/failed check metadata produces its own warning and unknown/unconfirmed archive check time; a verified basis and publication can still price. Preserve canonical SHA-256 revisions and all rules/multipliers/source conditions. No valid basis is overwritten or automatically deleted. First initialization is limited to a Provider with no prior cache/publication or archive records; an ambiguous existing state follows Q54, not bundled fallback.
5. Own `server.mjs` route/startup integration and the cost-producing request admission boundary. Before dashboard, Session page/detail, deprecated summary, refresh response or export preparation builds cost, await verification of that process's active archived basis. A reader may intentionally retain a prior verified published version until manual load. Failed latest-load cannot replace it; active-basis failure makes its new costs unknown. Do not secretly restore damaged storage from a GET. Projection availability changes invalidate guarded requests through the existing full-page reload. Q47 exports already prepared/started retain their verified admitted data, even if a file later changes.
6. Add same-origin `POST /api/pricing/load` for reader and writer processes to load the latest published rates. Keep `POST /api/pricing/refresh` writer-only. Add writer-only `POST /api/pricing/repair` and a distinct explicit UI action. Repair uses a previously verified complete retained basis, or fetches/validates a complete candidate through the existing fixed Provider source. It accepts no arbitrary file path or historical revision. Preserve confirmed invalid files in an app-local quarantine with unique names and no automatic deletion. If quarantine/publication fails, retain failure state and do not enable the candidate. Recheck any moved record: a now-valid record must be preserved/restored without replacement and repair must stop on conflict. Effective basis validity, successful publication and ownership are all required before cost recovery. Valid records and unrelated files are never overwritten or removed.
7. Return distinct ownership/publication/basis/metadata/repair failures without local paths or private owner identifiers. Extend `public/scripts/dashboard.mjs`, `public/scripts/i18n.mjs` and existing price controls to show writer/read-only state, explicit latest-load, repair and active verification/error status. Reuse request ownership rules; old Provider actions cannot publish late responses/errors or leave busy controls active. A successful load/repair updates the complete projection and requires a new export click after conflict. No automatic cross-process browser synchronization or history activation.
8. Extend existing ownership/pricing fixtures only where required; add focused pricing-ownership/recovery cases and copied actual multi-process HTTP fixtures. Update API/README/inventory and a delivery validation record. Recheck the Q42/Q43 normal workload and Q48 transfer boundary if per-request verification changes measured costs. Retain current cache/export assumptions and all selected accounting/calendar behavior. Do not add a database, dependency or background takeover.

## Acceptance for confirmed policies

- Ownership: two real copied-app processes sharing a pricing directory, separate ports, one writer and one reader; reader startup, automatic cadence and manual-load create no pricing files and make zero upstream fetch calls. Check both Providers, live-owner refusal, normal release/restart, abnormal exit, unknown/foreign/malformed owner, explicit safe unlock, ownership loss and failed-listen cleanup. Settings and pricing permissions must not depend on each other.
- Publication: inject archive and cache write/rename failures separately. New pricing activates only when its current publication succeeds. Archive-only candidates do not become current on restart. A failed older operation cannot roll back a later committed basis. Process interruption before/after basis publication and cache rename must restart into a verified published version or unknown cost, without selecting an unrelated archive. Include automatic/manual overlap, reader load during writer publication and new first-install publication.
- Verification: remove or corrupt the active basis after activation; the next cost response must detect it. Token totals remain correct and all KPI/model/trend/Session/detail/four export cost qualifiers agree. A pre-existing reader with a valid retained basis survives a failed latest load; a damaged retained basis becomes unknown. Reader actions never repair files. Check metadata failures retain valid cost while exposing untrusted timestamps. A completed old-version export stays byte-identical through refresh/revalidation.
- Compatibility: valid version-1 cache plus matching canonical archive remains readable; invalid source/Provider/basis fails. Empty first state differs from damaged existing state. No directory scan selects a historical winner; current-basis and no-history-switch policies remain. Missing/invalid published state cannot expose arbitrary file content or paths.
- Repair: reader refusal with no file/fetch changes, exact retained-basis offline recovery, validated fresh-source recovery when no trusted retained basis exists, corrupt-file quarantine with byte preservation, missing-record recreation, valid-record non-replacement, valid replacement during quarantine, interrupted quarantine/publish and failure before activation. No query silently repairs and no stale writer repairs after losing ownership. Do not call a quarantined corrupt record a verified pricing version.
- Desktop: root verifies writer versus reader controls, English/Traditional Chinese errors, manual latest load and full dashboard cost update, failed-load retained version, active-basis unknown cost and request races. Preserve native export guard/handoff/busy behavior. No mobile or tablet checks.
- Resources: preserve the selected 150000-observation query/export workload and numeric targets while adding active verification. Report observed latency/RSS and sampling limits; do not weaken the verification policy or silently raise targets. Final syntax, documentation links, intended diff and focused checks precede commit. No broad live contract harness or production rollout.
